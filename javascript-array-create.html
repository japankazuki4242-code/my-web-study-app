配列を作る・constとlet

配列を作る基本コード

3つの果物を入れた配列は、次のように作ります。

const fruits = ["りんご", "みかん", "バナナ"];

角括弧[ ]の中へ値を書き、値と値の間をカンマ,で区切ります。

作った配列をfruitsという変数へ入れているため、後からfruitsという名前でこの配列を使えます。

書き方を分けて読む
書き方 意味
const あとから別の値を再代入できない定数を宣言する
fruits 配列を入れる変数の名前
= 右側の値を左側の変数へ代入する
[ 配列の始まり
"りんご" 1つ目の要素
, 要素と要素の区切り
"みかん" 2つ目の要素
"バナナ" 3つ目の要素
] 配列の終わり
; 文の終わり

左から読むと、「配列をfruitsという変数へ代入する」というコードです。

constでも要素は変更できる

constで配列を入れた変数を宣言しても、配列の中にある要素は変更できます。

const fruits = ["りんご", "みかん"];

fruits[0] = "バナナ";

このコードでは、配列の1つ目の要素を「りんご」から「バナナ」へ変更しています。

[0]は1つ目の要素を指定する書き方です。詳しい読み方は、次の「要素とインデックス」で学びます。

constでは別の配列を再代入できない

constで宣言したfruits自体へ、別の配列を再代入することはできません。

const fruits = ["りんご", "みかん"];

fruits = ["ぶどう", "もも"];

1行目でfruitsへ配列を代入した後、同じfruitsへ別の配列をもう一度代入しようとしているためです。

constは「その変数へ別の値を再代入できない」と覚えましょう。

letでは再代入できる

letで宣言した変数には、あとから別の値を再代入できます。

let fruits = ["りんご", "みかん"];

fruits = ["ぶどう", "もも"];

このコードでは、fruitsへ新しい配列を再代入しています。

constとletの違い
宣言 再代入
const その変数へ別の値を再代入できない
let あとから別の値を再代入できる

配列自体を別の配列へ入れ替えない場合は、constで宣言できます。配列の要素を変更することと、変数へ別の配列を再代入することは別です。

間違えやすいポイント

誤解しやすい考え方
constなら配列の中身も絶対に変更できない

正しい考え方
constで宣言した変数へ別の値は再代入できないが、配列の要素は変更できる

constは「中身が絶対に変わらない」という意味ではありません。
