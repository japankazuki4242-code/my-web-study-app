元の配列と新しい配列

結果の形はメソッドごとに違う

配列メソッドを実行した後の動きは、メソッドによって違います。

元の配列そのものを変更するもの、新しい配列を作るもの、配列を作ることが目的ではないものがあります。

暗記するのではなく、実行前と実行後の値を比べながら確認しましょう。

5つのメソッドを整理する
メソッド 今回確認する動き
push() 元の配列を変更する
filter() 元の配列を変更せず、新しい配列を作る
map() 元の配列を変更せず、新しい配列を作る
forEach() 要素を1つずつ処理する
find() 条件に合う最初の要素を取得する
push()は元の配列を変更する 
const numbers = [1, 2, 3];

numbers.push(4);

console.log(numbers);

実行前
→ [1, 2, 3]

実行後
→ [1, 2, 3, 4]

numbers配列そのものへ4が追加されています。

filter()は新しい配列を作る 
const numbers = [1, 2, 3];

const filtered = numbers.filter(function (number) {
  return number >= 2;
});

元のnumbers
→ [1, 2, 3]のまま

新しいfiltered
→ [2, 3]

条件に合う要素を入れた、別の新しい配列ができます。

map()も新しい配列を作る 
const numbers = [1, 2, 3];

const doubled = numbers.map(function (number) {
  return number * 2;
});

元のnumbers
→ [1, 2, 3]のまま

新しいdoubled
→ [2, 4, 6]

各要素を変換した値を入れた、別の新しい配列ができます。

forEach()は1つずつ処理する 
const numbers = [1, 2, 3];

numbers.forEach(function (number) {
  console.log(number);
});

この例では、各要素を順番に表示することが目的です。

実行後も元のnumbersは[1, 2, 3]のままです。

今回は、forEach()を新しい配列を作るためには使っていません。

find()は最初の要素を取得する 
const numbers = [1, 2, 3];

const found = numbers.find(function (number) {
  return number >= 2;
});

結果のfound
→ 最初に条件に合う要素2

元のnumbers
→ [1, 2, 3]のまま

find()は新しい配列を作るのではなく、条件に合って見つかった1つの要素を結果にします。

実行順に沿って前後を確認する

① メソッドを実行する前の元の配列を確認する

② メソッドを実行する

③ 元の配列をもう一度確認する

④ 結果を別の変数へ保存している場合は、その値も確認する

この順番で見ると、「元の配列が変わったのか」「別の結果ができたのか」を区別できます。

確認問題

① 元の配列そのものへ要素を追加するメソッドは何ですか？

② 条件に合う要素から新しい配列を作るメソッドは何ですか？

③ 各要素を変換して新しい配列を作るメソッドは何ですか？

④ 条件に合う最初の1つを取得するメソッドは何ですか？

確認問題の答え

① push()です。

② filter()です。

③ map()です。

④ find()です。

今回の学習ポイント

push()は元の配列を変更します。

filter()とmap()自体は、元の配列を変更せず新しい配列を作ります。

forEach()は1つずつ処理し、find()は条件に合う最初の要素を取得します。
